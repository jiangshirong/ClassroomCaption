便携单文件与程序缓存

本方案用于正式发布版，开发版仍通过“启动开发版.vbs”直接运行。

1. 复制与启动
仍只需复制 ClassroomCaption.exe，不要求教室电脑安装 .NET 或开发工具。
第一次打开时，内置程序在本机自动解压。默认优先 E:\课堂字幕\程序缓存；E 盘不存在时使用 D:\课堂字幕\程序缓存。没有 E/D 盘或默认目录不能写入时，会请用户选择可长期保留的文件夹，不静默改放 C 盘。

2. 重启后复用
每个程序版本以完整程序内容的 SHA-256 作为目录名称。再次启动先校验缓存，完整时直接使用，文件缺失或损坏时重新解压。原生 DLL 缓存也位于同一版本目录内。只要该盘不受还原保护清除，重启后仍可复用。仅清空 C 盘系统临时目录不会清除这些程序缓存。

3. 与课堂记录分开
程序缓存不包含日常追加的课堂记录。设置、Key 和课堂记录继续使用现有 data 规则。新版使用不同的内容目录，不覆盖旧版目录或课堂资料。程序缓存可以手动删除，下次打开 EXE 会自动重建；不要把 data 当成程序缓存删除。

4. 完整性与异常
构建时先完整解压验证，确认每个字节与原程序相同。运行时使用 SHA-256 检查主程序，以及 .NET 需要展开的原生依赖。损坏的原生缓存会改名保留，再让 .NET 重新展开；不会递归删除无关文件。并发启动会共享一次解压。解压写入临时文件，成功后才原子替换，缓存目录不允许通过链接转向其他目录。

5. 体积与速度
本机内部样本从约68.6 MiB的普通自包含单文件，缩小到约49.1 MiB的缓存便携EXE，保留完整运行环境、中文字库、公式及降噪。缓存中的原程序约139 MiB，此外还有原生依赖，因此减少的是携带的EXE大小，不是运行后总磁盘占用。首次会增加解压和写盘时间；后续主要增加完整性校验开销。具体速度取决于教室电脑磁盘和处理器。

6. 构建与验证
publish-compact.ps1 使用 CachePayload 发布配置，再调用 build-cached-exe.ps1 生成原生启动器。Compact.pubxml 保留为传统 .NET 单文件配置。脚本只在明确调用发布时创建发布目录，不随开发版启动自动发布。
test-cached-exe.ps1 验证首次展开、跨进程复用、损坏修复、并发启动、Unicode路径、实际WPF主程序与原生组件、目录链接拒绝及错误元数据拒绝。测试不收音、不调用模型，也不能代替教室重启后的现场检查。

缓存位置的高级参数为 --program-cache-dir <独立缓存目录>；--data-dir 仍只影响原有数据保存位置。
