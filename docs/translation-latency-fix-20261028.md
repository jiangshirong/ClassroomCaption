# 实时翻译停滞修复

证据：用户截图显示俄语持续更新而中文停在旧片段。最近会话记录为约 79 秒发送音频、75 次识别更新、14 次翻译调用。旧记录没有应用/作废/失败细分，不能据此断定各失败原因的比例。

代码问题：原先最多 120 词的请求中，任意后缀在等待期间被 ASR 改写，整批译文都被丢弃。缩小批次时还必须限制前一暂译的回看范围，否则会反复请求相同前段而阻塞新词。

真实接口检查：旧下标协议的一个 11 词样本约 1.66 秒返回，但因模型分段未覆盖全部下标被拒绝。改用原文片段协议后，两段预置俄语短句已有一轮分别约 1.46 秒、1.40 秒成功应用；不代表课堂端到端延迟保证。

修改：
- 调度以 24 词作为初始窗口，避免在请求中积累很长的讲话；已有暂译边界仍保持完整。
- 限制回看，保证小窗口中能包含新词；前面已翻译内容作为上下文供参考。
- LLM 返回 ru/zh/complete，软件逐词核对 ru 与提供的原文并计算下标。
- LLM 返回正确的连续前缀但后续缺失或不匹配时，前缀以暂译显示；后缀仍待译，不伪造原文覆盖。
- ASR 修订后只应用未变更且完整的连续译文片段，不截断中文片段，不应用变更后的范围，不让旧结果覆盖新结果。
- 错误可见；统计请求成功应用、局部应用、作废和失败。

验证入口：CoreTests 普通执行只用虚构密钥和模型。显式 --live-translation 加数据目录仅发送内置短句到已配置的 DeepSeek 官方接口，可能产生调用费用；统计报告不保存 Key、请求头或课堂正文。WindowsTests 为离屏组件检查，不打开或操作桌面窗口。没有使用 Computer Use，没有生成便携包。

边界：实际课堂中的持续回改、网络波动和长时间延迟仍需后续观察；新增统计用于区分原因。音频未录制或重新整理。
