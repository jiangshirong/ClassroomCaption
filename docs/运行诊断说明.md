# 运行诊断

主程序点击“检测这台电脑”时，先采集当前 WPF 进程的信息，在现有 `data/diagnostics` 保存 `运行诊断-时间-随机编号.json` 和同名文本，再打开原有独立检测工具。独立工具输出的 `环境检测` 报告包含 `collectionContext.runtimeReport`，指向此次运行诊断。两份报告都应保留。

运行诊断不读取连接设置或凭证，不录音、不读取屏幕像素、不修改系统视觉效果、不调用模型。独立检测默认只查询音频设备和格式，不启动音频采集。其公共服务网络可达性检查仍保留，不携带 Key；单独测试可使用 `--no-network` 跳过。需要短时音频能力验证时，用户可明确勾选“另行测试麦克风”后检测，或明确传入 `--audio`，采集仅在内存。

## 报告字段

- `application`：实际进程路径、外层便携 EXE 路径（若存在）、版本、程序集 MVID 构建标识、进程/系统架构及运行环境。MVID 是本程序集构建标识，不是 Git 提交号。测试宿主运行时路径会如实指向测试进程。
- `visualEffects`：WPF 缓存中的 ClientAreaAnimation、Win32 当前动画/UI 效果、菜单/提示/列表等设置及相关注册表原始值。两种 API 的值可能不同，报告不会修改其中任何一个。
- `captionAnimationPolicy`：新版字幕逐字显示与字幕球动画独立启用，不跟随 ClientAreaAnimation；该字段记录程序策略，不伪装为实测帧数。部分装饰动效仍可跟随系统偏好。因此系统动画为 false，不能直接推断新版字幕动画被禁用。
- `session`：会话编号、远程标志、WTS 协议类型；不记录远程客户端名称、IP 或用户名。远程标志不保证识别所有第三方远控。
- `wpf`：当前进程的渲染能力等级、进程渲染偏好、主窗口 HwndTarget 渲染偏好及实际窗口 DPI。Tier 0 表示未报告硬件加速能力；Tier 2 也不能证明每个透明字幕窗口都由 GPU 渲染。独立 x86 Win32 工具不承载 WPF，因此它的 WPF 等级明确为 null，不用它代替主程序实际测量。
- `hardware`：CPU 型号、当前进程可用逻辑处理器数、总/可用内存和负载、显示适配器及驱动版本日期、多屏完整范围/工作区/DPI。适配器列表可能包含重复输出、未连接输出和虚拟显示器，不能据此推断软件实际使用哪一块 GPU。有效 DPI 受调用进程 DPI 感知方式影响，窗口实际 DPI 单独记录。
- `frameTiming`：约 1.2 秒内 WPF Rendering 回调的间隔中位数、P95、超过 50/100ms 的次数。持续时间可能因 UI 繁忙而变长。它不是 GPU/显示器实际呈现帧率；隐藏、遮挡和空闲也会影响结果。样本不足会明确标注，不自动认定“禁用了动画”或“掉帧”。

可选字段采用 `Status/Value/Reason`：成功为 `ok`，缺失为 `unavailable`，调用失败为 `failed` 并带原因。缺失的注册表配置不是“已关闭”；默认渲染偏好也不是“已启用硬件渲染”的证据。历史报告未采集这些信息，不能补算教室电脑当时的设置。

## 验证和构建

`scripts/build-probe.ps1` 构建静态依赖的 x86 独立工具；主程序后续构建会内嵌它。此操作不发布、不修改 dist。只修改 C++ 源码但不重建内嵌工具，不会更新主程序中的检测能力。

定向验证入口：`dotnet run --project tests/ClassroomCaption.WindowsTests -c Release -- --runtime-diagnostics-tests`。验证未知/失败原因、真实本机 API、双格式文件、构建/进程标识、凭证哨兵不进入报告，以及实际启动内嵌工具的无音频/无网络报告关联。验证窗口保持隐藏，不使用 Computer Use。隐藏测试的帧回调统计不作为教室动画性能验收。

软件渲染、远程桌面、旧系统与多显示器不同缩放的实际行为，仍需对应现场运行新版后查看报告；本机采样不能替代这些现场结论。
